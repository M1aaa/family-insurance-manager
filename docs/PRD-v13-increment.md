## 10.1 版本背景与目标

**用户原话**：
> 1. 保单录入时被保人要能够多选，因为有些一张保单能保多人。
> 2. 家庭成员栏次，需要按照家庭成员统计已有保障类型（比如医疗、意外、重疾等）。
> 3. 险种增加分红险。
> 4. 保单列表能够直接点击查看 PDF 保单，目前功能只能点编辑进去查看。

**要解决的问题（大白话）**：
1. **「一张保单保全家，现在只能填一个人」**：全家共享型保单（如家庭医疗险、一张主险带多个被保人）目前只能记一个被保人，导致其他被保人的保障在统计里**凭空消失**，家庭财务负责人看不到"谁被这张保单保了"。
2. **「不知道每个人身上有什么保障」**：成员页只有"保单数 / 年保费"，看不到"这个人有没有重疾险、有没有意外险"，**保障缺口**无法一眼发现。
3. **「储蓄型保单没处归类」**：分红险（如增额终身寿、分红年金）只能塞进"其他"，统计口径失真。
4. **「看电子保单要点编辑，多一步」**：列表页想看 PDF 得先进编辑弹窗，高频操作多绕一步。

**本次目标（3 个正交目标）**：
1. **保障归属更真实**：一张保单可记录**多个被保人**，且统计时按人**分摊保费**，让"每个人身上挂了哪些保障、多少钱"准确且不重复计数。
2. **保障缺口一眼可见**：家庭成员页按成员汇总**已有保障类型（险种 + 张数）**，快速识别"谁还缺重疾/意外"。
3. **电子保单随取随用**：保单列表**一键直达** PDF，无需进入编辑弹窗。

**范围边界（一句话）**：本次把「多被保人 + 成员保障类型统计」做扎实（P0），「分红险」「列表直达 PDF」一并交付（P0）；多被保人下的**高级归属策略**（如自定义分摊比例）列为 P2 不做。

## 10.4 关键产品决策（本次必须澄清的 4 点）

### 决策 a：多被保人后「被保人」列怎么展示、筛选怎么工作

| 项 | 决策 |
|---|---|
| 列表「被保人」列 | 多个姓名用「、」分隔。**≤2 人**：`张三、李四`；**≥3 人**：`张三、李四 等 N 人`，并在单元格 `title` 属性中给出**完整名单**（鼠标悬停可见）。 |
| 筛选下拉 | 保持"选成员"交互不变，语义由"等于"改为**"包含"（any-of）**：选中张三 → 命中"被保人中含张三"的全部保单。**理由**：用户选某人的意图是"看这个人的保障"，只要该保单保了他就应命中，而非仅命中"只有他一个人"的保单。 |
| 看板分布图 | 一张 N 人保单在「按被保人」分布中**出现在每个被保人下**（保单数各计 1，保费按 10.4-b 分摊）。 |
| 待缴清单 / 逾期面板 | 「被保人」列展示规则与列表一致（≤2 全列，≥3 截断 + title）。 |
| 不整行点击 | 列表**不**改为整行点击（会与勾选框、行内按钮冲突）；查看 PDF 用独立「电子保单」列按钮（见决策 d）。 |

### 决策 b：一单多被保人时「按成员统计」的保费口径 ★（直接影响数字）

**决策：保费类指标按人头「均摊」；保单数类指标「全额（按被保障次数）」。**

| 指标 | 口径 | 说明 |
|---|---|---|
| 年化保费 / 近 60 天待交保费 / 累计已缴保费（byMember） | **均摊**：`分摊额 = 指标值 ÷ 被保人数` | 保留 2 位小数，除不尽的**尾差归排序最后一名被保人**，保证 Σ分摊额 = 原值 |
| 保单数 / 生效中保单数（byMember） | **全额**：一张 N 人保单对每个被保人各计 1 | 该列回答"这个人被几张保单保障"，非"总共有几张保单" |
| 顶部「年度总保费 / 近 60 天待交」卡片 | **不变**：仍按保单去重、每张只计一次全额 | 与 v1.2 **逐值相同**，反映真实年度支出 |

**理由（为什么保费要分摊、保单数不分摊）**：
1. **保费是"一笔钱"，不能重复计**：一张年缴 6000 的全家医疗险，若给张三、李四各记 6000，则"按成员统计的保费之和 = 12000"，**大于**真实年度总保费 6000，用户会看到"分项加起来比总数还多"的诡异数字，直接失去信任。均摊后 **Σ分摊 = 总保费**，可对账。
2. **保单数是"保障覆盖次数"**：一个人确实**被**这张保单保障了，记 1 张符合直觉；"0.5 张保单"没有意义，故保单数全额计。两类指标**刻意不同**，在 UI 上对保费列标注「分摊」并 hover 说明"该保单由 N 人共保，保费按人头均摊"。
3. **顶部卡片是"真实支出"**：家庭财务负责人准备资金看的是**总共要交多少钱**，必须按保单去重、保持 v1.2 口径不变。

**算例**（沿用 `ARCHITECTURE.md` 算例集 A 数据；`today=2025-05-20`）：
新增保单 **H**：平安 · 全家医疗险，年缴 6000，被保人 = 张三(m1) + 李四(m2)，生效中。

| 口径 | 张三 | 李四 | 合计 | 与"年度总保费"关系 |
|---|---|---|---|---|
| **分摊（采用）** | +3000 | +3000 | **6000** | Σ = 6000 ✅ 可对账 |
| 全额（不采用） | +6000 | +6000 | **12000** | Σ = 12000 ≠ 6000 ❌ 重复计数 |

> 顶部「年度总保费」卡片：H 计 **6000（一次）**，其余保单同 v1.2 → 卡片值与 v1.2 一致。

### 决策 c：需求 2「已有保障类型统计」展示什么维度

**决策：P0 展示「险种 + 张数」（标签形式）；保费作为点击展开的明细（P1 内一并交付）。**

| 维度 | 是否展示 | 呈现方式 |
|---|---|---|
| 保障类型清单（险种） | ✅ P0 | 标签 chip，如 `[重疾险]` |
| 该类型张数 | ✅ P0 | 标签内 `[重疾险×2]` |
| 该类型年化保费（分摊后） | ✅（展开明细） | 点击标签展开：`张数 / 年化保费 / 生效中张数` |
| 投保人/被保人维度 | ❌ | 固定按**被保人**归属（与现有「按被保人」统计一致） |
| 已退保/已失效保单 | ❌（默认不计） | 口径与「在保人数」一致：仅统计 `生效中 / 已缴清` |

**理由**：用户原话只要求"统计已有保障类型"，故**类型清单是核心**；加"张数"成本极低且能回答"够不够"（如"只有 1 张重疾"）；保费信息密度高，放进**展开明细**避免成员表横向过宽。排序：**张数降序 → 险种枚举顺序**，保证多成员间可横向比较。无保障时显示「暂无保障」灰字。

### 决策 d：需求 4「直接点击查看 PDF」——多附件时点击行为

**决策：按附件数量分三种行为；采用独立「电子保单」列按钮，不做整行点击。**

| 附件数 N | 点击行为 |
|---|---|
| `N = 0` | 单元格显示「—」，**不可点击**（或点击提示"该保单暂无电子保单"） |
| `N = 1` | **直接**在新标签页打开该 PDF（沿用现有 `inline` 查看接口） |
| `N ≥ 2` | 弹出**附件选择弹层**：列出全部文件名（点文件名即查看），每项带「下载」 |

**理由**：① 单附件直接打开最省一步，符合用户"直接点击查看"的诉求；② 多附件时"点开哪一个"有歧义，用**选择弹层**消歧，比"只开第一个"更诚实；③ **不整行点击**：列表行已有勾选框与行内按钮（编辑/删除/联系方式），整行点击会误触，独立列按钮更稳。④ 保留"编辑弹窗内附件管理（上传/删除）"原路径不变——列表页只做**查看/下载**的快捷入口。

## 10.5 字段与口径定义（变更部分）

### 10.5.1 保单 → 被保人 关系变更

| 项 | v1.2 现状 | v1.3 变更 |
|---|---|---|
| 被保人 | `Policy.insured_id` 单外键（`NOT NULL`） | **一单多被保人**（≥1）。产品层要求：可多选、可指定 1 名主被保人 |
| 投保人 | `Policy.policyholder_id` 单外键 | **不变**（仍单人） |

> 存储结构（如"新增保单-被保人关联表 + 保留主被保人字段"）由**架构师设计**；本 PRD 只约束产品行为与兼容性要求（见 10.7）。

### 10.5.2 新增 / 变更的 API 字段（camelCase）

| 字段名 | 类型 | 说明 |
|---|---|---|
| `insuredIds` | `string[]` | 被保人成员 id 列表（≥1）。**替换**原 `insuredId`（单人） |
| `primaryInsuredId` | `string` | 主被保人成员 id，必须 ∈ `insuredIds` |
| `insuredId`（**兼容保留**） | `string` | 为向后兼容，响应中保留 = `primaryInsuredId`（读旧字段的前端/脚本不受影响）；请求侧建议统一用 `insuredIds` |
| `insuredNames` | `string[]` | 被保人姓名列表（响应派生字段，供列表直接渲染） |
| `attachmentCount`（**既有**） | `int` | 列表「电子保单」列直接用（v1.2 已有） |

### 10.5.3 年龄相关期限的口径（多被保人下）★

「至某年龄 A」「交至某年龄 A」依赖被保人出生日期。多被保人年龄不同时，**统一以「主被保人」的出生日期为准**。

| 项 | 口径 |
|---|---|
| 总缴费期数（交至某年龄） | `max(0, A − 主被保人 生效时周岁) × 每年期数` |
| 是否在保障期内（至某年龄） | `今天 ≤ 主被保人出生日 + A 年` |
| 表单提示 | 选定主被保人后，在期限字段旁提示"年龄相关期限以**主被保人**（XXX）为准" |

**理由**：与 v1.2 单人语义**无缝延续**（单人时主被保人=唯一被保人，结果逐值相同）；可预期、用户可控。若以"最大/最小年龄"为准，用户无法预知计算基准，易生困惑。

### 10.5.4 险种枚举（新增值）

`InsuranceType` 新增 **`分红险`**，建议排序位置（供架构师/前端参考）：

```
重疾险 / 医疗险 / 意外险 / 寿险 / 年金险 / 分红险 / 教育金 / 车险 / 财产险 / 其他
```

> 插入在「年金险」之后（同为储蓄/理财型，便于分组认知）。前端下拉**无需改动**——由 `/api/meta/enums` 自动获得。

## 10.7 对既有功能的影响与兼容性

| # | 既有功能 | 影响 | 兼容性处理 |
|---|---|---|---|
| 1 | **存量保单数据**（NAS 真实数据） | 被保人由单值变多值 | 启动时**幂等自动迁移**：把每张保单 `insured_id` 写入"被保人集合"，并将该人设为主被保人。**用户零操作**，失败不阻塞启动（仅告警）。见 R-42。 |
| 2 | **年度总保费 / 近 60 天待交保费卡片** | 多被保人不改变"按保单去重"口径 | **数值与 v1.2 逐值相同**；单人保单不变。 |
| 3 | **按成员统计（byMember）** | 保费需分摊、保单数按次计 | 单人保单分摊系数=1，**数值不变**；仅多被保人保单按 10.4-b 分摊。 |
| 4 | **在保人数（insuredPersonCount）** | 多被保人下**去重**口径天然成立 | 口径不变（去重被保人，且 `status ∈ {生效中, 已缴清}` 且在保障期内）；多被保人只会让该数更准。 |
| 5 | **calc_schedule（含 k_max / 期限计算）** | "至某年龄"依赖被保人生日 | 统一以**主被保人**生日为准（10.5.3）；单人保单**逐值不变**。 |
| 6 | **删除成员（409 MEMBER_IN_USE）** | 引用来源增加"被保人集合" | 检查投保人 + 被保人（去重），文案含关联保单数；见 R-46。 |
| 7 | **保单筛选（insuredId）** | 由"等于"变"包含" | 语义升级；单人保单结果不变。 |
| 8 | **列表附件（编辑弹窗内）** | 新增列表页直达入口 | 原路径**保留不变**；列表页只做查看/下载快捷入口。 |
| 9 | **批量编辑（v1.2）** | 不涉及被保人字段 | **不受影响**（批量编辑仅覆盖售后字段）。 |
| 10 | **险种枚举** | 新增「分红险」 | 前端经 `/api/meta/enums` 自动获得，**前端零硬编码**。 |
| 11 | **API 字段 `insuredId`** | 语义变为主被保人 | 响应保留 `insuredId = primaryInsuredId`，**旧调用不破**；新增 `insuredIds` / `primaryInsuredId` / `insuredNames`。 |

**⚠️ 兼容性风险（须架构师核实并处理）**：`policies.insurance_type` 列若存在**枚举 CHECK 约束**（架构文档 3.1 声称"VARCHAR + CHECK"），则**新增「分红险」会违反旧 CHECK**，需迁移（SQLite 需重建表或更新约束）；若实际为**纯 VARCHAR 无 CHECK**，则零迁移。请架构师在实现前**核实该列约束的真实情况**并给出迁移方案。

## 10.8 边界与异常场景

| # | 场景 | 期望行为 |
|---|---|---|
| B-24 | **多被保人 + 「至某年龄 / 交至某年龄」** | 以**主被保人**生日为准计算；表单旁给出"以主被保人为准"提示；单人保单不受影响。 |
| B-25 | **未勾选任何被保人** | 阻止保存，提示"请至少选择 1 名被保人"。 |
| B-26 | **取消勾选的人恰为主被保人** | 自动把主被保人转移到剩余被选中成员的第一位（或阻止取消并提示，二选一，见 Q17）。 |
| B-27 | **存量单被保人保单** | 迁移后 = 1 名被保人 + 该人为主被保人；全部数值与 v1.2 一致。 |
| B-28 | **多被保人保费除不尽** | 保留 2 位小数，**尾差归排序最后一名被保人**，保证 Σ分摊额 = 全额。 |
| B-29 | **多被保人保单，成员被删除** | 任一被保人被引用即 409；引用计数去重，文案含关联保单数。 |
| B-30 | **列表附件数 = 0 时点击** | 显示「—」不可点击，或点击提示"该保单暂无电子保单"。 |
| B-31 | **列表附件数 ≥ 2 时点击** | 弹附件选择弹层，点文件名查看、可下载。 |
| B-32 | **新增「分红险」后，存量库枚举约束** | 若存在 CHECK 约束需迁移（见 10.7 风险）；纯 VARCHAR 则无感。 |
| B-33 | **成员页保障类型统计口径** | 仅统计 `生效中 / 已缴清` 保单；已退保/已失效不计入；无保障显示「暂无保障」。 |
