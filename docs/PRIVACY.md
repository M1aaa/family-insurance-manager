# 数据边界与脱敏说明

这个项目处理的是**真实家庭保单信息**。仓库对外可见的内容经过脱敏，本文件说明边界在哪里、
做了什么处理、以及如果将来要公开仓库还需要补什么。

## 一、绝不进入版本库的内容

| 路径 / 类型 | 内容 | 处理方式 |
|---|---|---|
| `data/insurance.db` | 真实保单、家庭成员、缴费记录 | `.gitignore` 排除，仅保留 `data/.gitkeep` |
| `data/*backup*` | 历史备份库 | 同上（按整目录排除，不依赖后缀匹配） |
| `data/attachments/*.pdf` | 电子保单原件 | 同上 |
| `data/*.log` | 运行日志 | 同上 |
| `dist/*.tar` | 镜像文件（单个约 157 MB） | 排除；改由 GitHub Releases 发布 |
| `docs/screenshots/` | 界面截图，含真实姓名与金额 | 排除，**本地完整保留** |
| `.workbuddy-ai/` | AI 协作记忆与迭代手册 | 排除（属工作文件，非项目代码） |
| `.env` / `*.pem` / `*.key` | 凭据与密钥 | 排除 |

`.git/hooks/pre-commit` 会在提交前再拦一道，命中上述路径或后缀直接拒绝（已实测生效）。

## 二、文档做了哪些脱敏

原始开发记录里带有真实使用数据，已替换为结构等价的示例值：

| 位置 | 原内容 | 现内容 |
|---|---|---|
| `docs/PRD.md` §10.4 | 应缴 5900 / 未缴 4800 / 差 1100，标注「用户真实数据」 | 应缴 6,000 / 未缴 4,000 / 差 2,000，标注「示例数据」 |
| `overview.md` v1.4 节 | 真实保单明细表（产品名 + 逐单金额） | 示例保单表（示例医疗险/意外险/重疾险） |
| `overview.md` v1.3 / v1.4 节 | 真实年度总额 22,200 | 24,000 |
| `overview.md` v1.6 节 | 车险 2,500、医疗险 100 | 2,800、120 |
| `docs/qa-report-v14.md` | 真实库交叉验证表 | 示例数据交叉验证表 |
| `docs/qa-report-v15.md` | 真实服务 JSON `5900.0`、被保人姓氏 | `6000.0`、虚构成员名 |
| `docs/DEVELOPMENT-HISTORY.md` | 引用真实姓氏与金额 | 改为「某成员」，不含量 |

替换原则：**保留数量关系**（应缴 − 未缴 = 差额，且差额来自两张「已缴完」保单），
只换绝对值。这样文档仍然能验证口径，但不含真实财务信息。

## 三、仍然保留的虚构数据

`tests/conftest.py` 中的「张三 / 李四 / 小张 / 王五」是**测试夹具**，不是真实家庭成员；
「平安 / 人保 / 国寿」是通用公司名，用于覆盖不同枚举值。这些留在仓库里没有隐私问题。

同样，`docs/ARCHITECTURE.md` 的算例集 A/B/C（年度 17,000、14,500 等）由测试夹具推导，
属于虚构基准，**是口径的唯一真源，不要为了"脱敏"去改它**——改了会让测试断言与文档对不上。

## 四、镜像为什么不含数据

`Dockerfile` 只做两处拷贝：

```dockerfile
COPY app ./app
COPY static ./static
```

没有 `COPY data`，`.dockerignore` 也排除了 `data/`。
镜像里只有代码与静态资源，运行时通过 volume 挂载宿主目录提供数据。
`step5_final_audit.py` 会断言「应用层文件与仓库源文件逐字节一致」，可反向证明镜像里没有夹带数据。

## 五、转为公开仓库前的处理（已完成）

本仓库在改为公开前做了以下清理：

1. **设备型号**：文档、compose 与构建脚本中的具体 NAS 型号已改为「NAS / 极空间 NAS」，只保留品牌，不暴露具体硬件。
2. **本机绝对路径**：所有 `C:\Users\<用户名>`、`D:\...` 路径改为占位符（`<repo>`、`<临时目录>`）；
   离线打包脚本改为按「脚本所在目录的上两级」推导仓库根、中间产物写系统临时目录，
   可用 `IMGBUILD_REPO` / `IMGBUILD_WORK` 覆盖。
3. **QA 原始输出**：删除 14 个 `_qa_*.txt` / `_qa_*.json` 运行产物（含本机路径与临时目录），
   保留可复现的脚本（`qa_*.py` / `qa_*.cjs`）。
4. **作者环境描述**：去掉「本机 WSL 被企业策略禁用」这类只对作者机器成立的信息，改为通用的兼容性说明。
5. **截图**：仍不入库；如需展示界面，用测试夹具数据重截一套。
6. **提交历史**：已重写为单一干净提交。**只改当前文件是不够的**——旧提交里仍保留脱敏前的文档，
   必须重写历史并强制推送，否则任何人翻 `git log` 就能看到原始数据。

公开后仍然**不会**进入仓库的：`data/`（真实库/备份/PDF）、`dist/`（镜像）、
`docs/screenshots/`（真实界面）、`.workbuddy-ai/`（内部记录）、任何密钥。

## 六、发布镜像与代码的关系

- 代码与文档在仓库里（公开）。
- 镜像 tar 走 Releases（附件），内容只有 `app/` + `static/`，不含数据。
- 两者都不包含任何家庭成员信息、真实保费或保单原件。
